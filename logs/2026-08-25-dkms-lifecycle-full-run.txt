===== PREDICTION for LEG 6, written before running it =====
AUTOINSTALL="no", so Debian /etc/kernel/postinst.d/dkms runs `dkms autoinstall`
and SKIPS this module. Predicted after upgrading to 6.12.96 and rebooting:
  - dkms status shows the module installed for 6.6.51 ONLY
  - /lib/modules/6.12.96*/updates/ has no morse or dot11ah
  - morse does not load, no interface bound to morse_spi, HaLow DOES NOT come up
That result is the measurement of what AUTOINSTALL="no" costs. Leg 7 then does
the cross-kernel install by hand, which is the path that has to be shown safe
before AUTOINSTALL="yes" is worth trying.

===== LEG 6 RESULT — the prediction was WRONG, and the state was contaminated =====
Two separate things went wrong and they must not be conflated.

1. THE UPGRADE FAILED, and my procedure caused it. `apt-get -y full-upgrade` ran
   detached with no tty and no conffile policy. dpkg hit a conffile prompt on
   /etc/initramfs-tools/initramfs.conf and died with "end of file on stdin at
   conffile prompt". initramfs-tools never configured -> linux-image-6.12.96
   never configured -> its postinst never ran -> NO modules.dep for 6.12.96 at
   all. The board booted 6.12.96 with zero loadable modules: no brcmfmac, hence
   no wlan0, hence it vanished from the house network. Nothing to do with morse,
   which could not have loaded either.
   `-y` answers apt, not dpkg. The fix is DEBIAN_FRONTEND=noninteractive plus
   -o Dpkg::Options::=--force-confold, and that repaired it.

   Consequence: the "no morse on the new kernel" observation taken right after
   that reboot proves nothing about AUTOINSTALL. No module could load. An
   elimination is only valid in the state it was measured in.

2. AUTOINSTALL="no" DOES NOT DISABLE AUTOINSTALL. Once dpkg was repaired the
   kernel postinst ran /etc/kernel/postinst.d/dkms, and dkms built and installed
   morse for BOTH 6.12.96+rpt-rpi-v8 and 6.12.96+rpt-rpi-2712 by itself.
   Cause, read from /usr/sbin/dkms line 2225:
       # if the module does not want to be autoinstalled, skip it.
       if [[ ! $AUTOINSTALL ]]; then continue; fi
   That tests for EMPTY, not for "no". Any non-empty value is truthy, so
   AUTOINSTALL="no" behaves exactly like "yes". To actually disable it the
   variable must be absent or empty. dkms 3.0.10, Debian bookworm.
   The staged dkms.conf did contain AUTOINSTALL="no" (line 34) -- checked, so
   this is dkms semantics and not a lost setting.

   Consequence: the cross-kernel AUTOMATIC rebuild has now been demonstrated,
   accidentally and successfully -- but the safety measure we thought we had was
   never in effect.
