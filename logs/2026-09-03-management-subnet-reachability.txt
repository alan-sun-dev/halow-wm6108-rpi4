The gateway answers hop 1 for both and forwards only one of them. Silence at
hop 2 for 10.41.0.208 means the VLAN gateway discarded it rather than
forwarding it, so no packet ever reaches 192.168.0.1 or the AP.

===== AP rule counters =====
		ip saddr { 192.168.101.0/24, 192.168.200.0/24 } tcp dport 22 counter packets 20 bytes 1268 accept comment "!fw4: Allow-SSH-mgmt-subnets"
		ip saddr { 192.168.101.0/24, 192.168.200.0/24 } ip daddr 10.41.0.0/16 icmp type echo-request counter packets 0 bytes 0 jump accept_to_lan comment "!fw4: Allow-mgmt-subnets-ping-halow"
		ip saddr { 192.168.101.0/24, 192.168.200.0/24 } ip daddr 10.41.0.0/16 tcp dport 22 counter packets 0 bytes 0 jump accept_to_lan comment "!fw4: Allow-mgmt-subnets-ssh-halow"

The input rule is carrying traffic. The two forward rules into 10.41.0.0/16
remain at zero: nothing addressed to the HaLow segment has ever arrived.
Earlier the same test from 192.168.200.151 produced an identical result, and
a tcpdump on the AP's eth0 saw the control ping to 192.168.108.5 in the same
window while seeing no packet at all for 10.41.0.208.
