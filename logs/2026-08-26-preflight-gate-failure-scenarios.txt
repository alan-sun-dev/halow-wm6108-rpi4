A STRUCTURAL POINT ABOUT THE INITRAMFS CHECK, NOT A BUG
  /boot/firmware/initramfs8 can hold one image at a time, and it holds the
  running kernel's. So for any OTHER +rpt-rpi-v8 kernel the check must FAIL --
  correctly, because the firmware really would load a stale initramfs. The
  2712 slot is separate (initramfs_2712), which is why that case PASSes the
  initramfs line while failing every module line.
  Consequence: the remedy for that particular FAIL is not "build the module".
  It is to make the target kernel the default so raspi-firmware regenerates
  the FAT copy. Do not read it as a DKMS fault.

THE ONE CHECK STILL NEVER SEEN FIRING ON HARDWARE: "dpkg clean"
  This is the check with the most history behind it -- an unattended
  apt full-upgrade once died on a dpkg conffile prompt, linux-image's postinst
  never ran, and no module of any kind could load on that kernel. Faking that
  state on a soaking board is not worth it, so the awk was exercised on
  synthetic dpkg -l input instead:

      clean input (ii / hi / rc / un)          -> notok=0   correct
      dirty input (adds iF and iU)             -> notok=2   correct
      held package (hi rpi-eeprom)             -> NOT counted as a fault, correct

  So the check discriminates. It has still never fired against real dpkg
  output, and that remains untested.

THE "dpkg clean" CHECK, EXERCISED ON SYNTHETIC INPUT
================================================================
The check:
    notok=$(dpkg -l | awk 'NR>5 && $1 !~ /^(ii|hi|rc|pn|un)$/ {n++} END{print n+0}')

Clean input — ii bash / hi rpi-eeprom / rc oldpkg / un nevertherepkg:
    notok=0                                     correct
Same input plus two half-done states:
    iF  linux-image-6.12.96   half-configured -- postinst never ran
    iU  raspi-firmware        unpacked, not configured
    notok=2                                     correct
The held package (hi rpi-eeprom) is NOT counted as a fault  correct
    — a hold is deliberate here and must not read as damage.

So the check discriminates between the two states it is used to distinguish.
It has still never fired against real dpkg output on this hardware; that is
the one part of the gate with no live evidence behind it.
